# KataCR LiveLoop 贡献清单

本文档区分上游 KataCR 的原始工作与本适配线新增的工程工作，避免把继承内容和新增内容混在一起。

## 上游继承内容

以下内容来自 [wty-yy/KataCR](https://github.com/wty-yy/KataCR)，不应在项目介绍或提交说明中表述为本人的原创：

- KataCR 的整体研究目标、核心代码组织和感知-状态-动作-奖励抽象。
- YOLOv8 组合检测、PaddleOCR 接口、分类器和原始视觉特征设计。
- StARformer、DT 等策略模型结构、训练方法、原始模型权重和评估结果。
- 原始训练/回放数据集、数据生成流程和展示材料。
- 原项目中的手机交互思路、坐标布局假设及原始训练营验证入口。

## 本适配线新增或重构内容

### 运行时与硬件适配

- WSL2 + Ubuntu 24.04 + Python 3.11 的部署整理。
- JAX GPU 链路、CUDA 编译工具诊断、Orbax checkpoint 跨设备恢复兼容。
- YOLO 推理 GPU 化验证，以及 Paddle/PaddleOCR GPU/CPU 回退路径。
- 环境检查、性能计时和运行结果清洗工具。

### 离线评估与可观测性

- 离线评估器的输入视频、输出目录、保存/显示、确定性和详细日志参数化。
- ROI 裁剪、OCR 复用、关键帧导出和轻量 OpenCV 回放工具。
- state、action、reward、识别结果和每阶段耗时的记录整理。
- 对 `state_update`、`sar_get`、`visual_fusion` 等阶段的拆分与性能定位。

### MuMu 实时实验

- Windows MuMu 与 WSL2 之间的 ADB 网络通信探测。
- 截屏获取、页面状态识别、训练营流程处理和动作安全边界。
- 卡牌/目标坐标映射、模拟器比例适配、动作节流和点击结果日志。
- 从离线视频入口到 MuMu 实时闭环的工程化验证脚本。

### 工程化与文档

- Windows 一键启动、WSL 启动和 GPU 验证脚本。
- 中文项目交接、阶段复盘、性能记录和故障排查文档。
- 将个人绝对路径、运行产物和实验性内容与公开代码边界分离。

## 证据与边界

- 以上新增内容以本仓库的代码、脚本、文档和测试结果为证据。
- “打通链路”表示在本人的 WSL2、GPU 和 MuMu 环境中完成过验证，不代表对所有设备、版本或模式都保证可用。
- “自动下牌”表示 ADB 层面的屏幕点击执行；它不等同于新增了训练模型，也不改变上游策略模型的训练能力。
- 模型强弱应通过固定输入、识别准确率、动作有效率、延迟和多局结果综合评估，不能只用一局胜负归因。

## 面向上游的候选贡献

如果向上游提交 Pull Request，建议保持小而独立，并只提交可复用改动：

1. 离线评估器参数化与输出路径兼容。
2. PaddleOCR GPU/CPU 回退和设备检查。
3. Orbax/JAX checkpoint 跨设备恢复。
4. 缺少辅助权重时的明确降级模式。
5. 与具体模拟器无关的 ADB 输入后端抽象。

MuMu 专用脚本、个人路径、账号环境、实验日志和本地启动器应留在个人适配仓库，不直接混入上游 PR。
