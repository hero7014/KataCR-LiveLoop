# 上游 PR 拆分图

目标仓库：[wty-yy/KataCR](https://github.com/wty-yy/KataCR)。每个 PR 都应从上游 `master` 的干净基线开始，只包含一个可以独立评审和回退的主题。

## PR 1：离线评估器参数化

**目的**：让视频路径、输出目录、保存/显示、确定性运行和详细日志可以通过参数控制，减少修改源码才能评估的问题。

**应包含**：`katacr/policy/offline/eval.py`、`katacr/policy/offline/eval_no_delay.py` 及必要的通用参数解析。

**不应包含**：个人视频路径、MuMu 坐标、Windows 启动器、运行日志和模型权重。

## PR 2：OCR 设备选择与回退

**目的**：在 GPU 可用时使用 Paddle/PaddleOCR，在不满足条件时给出明确诊断并回退 CPU。

**应包含**：`katacr/ocr_text/paddle_ocr.py` 的设备选择、初始化检查和最小测试。

**不应包含**：本机 CUDA 安装包、绝对路径和特定 Paddle wheel 文件。

## PR 3：JAX/Orbax checkpoint 设备兼容

**目的**：允许在不同设备或不同运行时恢复 checkpoint，并在失败时提供可读错误。

**应包含**：checkpoint 管理和设备映射的通用改动，以及不依赖账号环境的测试。

**不应包含**：本机权重目录、GPU 型号硬编码和整套运行环境快照。

## PR 4：辅助模型缺失时的明确降级

**目的**：当可选的圣水/分类辅助权重不存在时，程序能够明确提示并以受限模式继续，而不是在深层调用中崩溃。

**应包含**：分类器加载、离线评估入口和降级状态的通用处理。

**不应包含**：某个私人模型目录或只服务单套卡组的默认权重。

## PR 5：设备无关的 ADB 输入后端

**目的**：抽象截屏和点击接口，使手机、模拟器或其他 ADB 设备可以由配置选择。

**应包含**：设备接口、坐标变换、连接检查和 dry-run 测试。

**不应包含**：MuMu 专用窗口坐标、账号流程、训练营按钮序列和自动连点脚本。

## 保留在个人适配仓库

- MuMu 专用启动器、ADB 可执行文件路径和设备端口。
- 账号相关页面流程、训练营按钮坐标和实际对局日志。
- 本人的 GPU 安装记录、截图、视频、权重和性能实验结果。
- Codex/插件计划、对话交接记录和未完成的个人任务清单。

这样组织后，个人仓库可以完整展示 KataCR LiveLoop 的工程化落地；上游 PR 则只呈现可复用的技术改进，贡献记录更清晰，也更容易被维护者接受。
